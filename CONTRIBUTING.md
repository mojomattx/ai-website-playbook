# How to Suggest a Change

Found a rule that's wrong, missing, or unclear?

Tell us.

## Two ways to do it

### Open an issue

Go to the Issues tab of this repo and click New issue.

Say what should change, and why.

### Edit the file and open a pull request

Open the file on GitHub and click the pencil icon to edit it.

Make your change, then open a pull request.

A pull request is a proposed change that we review before it goes in.

## What makes a good suggestion

- It applies to any website, not just yours.
- It says why the rule matters, and what goes wrong without it.
- It has a source or real experience behind it, like an official guide or something that happened on a site you worked on.
- Every new rule comes with at least one checklist item: a yes or no line that a person or an AI can check.

A rule for one site only belongs in that site's own setup file, not here.

## How every step and rule is written

Every new step and every new rule meets these four tests, on top of the list above.

- It's actionable: it gives concrete steps someone can follow today, not vague advice.
- A complete beginner can understand it, even someone who knows nothing about websites or marketing, and every technical word is explained in plain words the first time it appears.
- It shows what doing it brings you, for example it saves time, makes money, or avoids a problem later.
- It isn't already in the playbook: search the playbook first, and if another rule already says the same thing, improve that rule instead of adding a new one, so the playbook stays lean.

## Who decides

MojoSons Media reviews the suggestions and decides what goes in.

We may change the wording so it fits the rest of the playbook.
